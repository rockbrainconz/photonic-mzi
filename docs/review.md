**本项目是独立设计和编写的原创实现。** 为验证分解公式、退化输入和工程边界，
测试目录另行收录了一份 MZI 对照样例：
[`tests/_reference_comparison.py`](../tests/_reference_comparison.py)。
下文简称「对照样例」；它不是本项目源码的起点，也没有被用于派生本项目实现。

结论先说：**核心数学链条是对的**，SVD → 酉矩阵 → MZI 网格的思路、消元公式的推导、
正向传播的共轭转置逆序施加，全都正确 —— 随机稠密矩阵能稳定跑到 1e-14 量级。
但有 **1 个会静默算错结果的真 bug**，以及若干物理建模上的简化值得补。

## 一、正确性 Bug（严重）

### B1. 两个退化分支的取值写反了 → 结构化矩阵全部静默算错

```python
if np.abs(y) < 1e-15:
    theta = 0.0          # ← 错，这里应该是 pi/2
    phi   = 0.0
elif np.abs(x) < 1e-15:
    theta = np.pi / 2.0  # ← 错，这里应该是 0
    phi   = 0.0
```

**根因**：`mzi_transfer_matrix(0, 0)` 并不是单位阵，而是**交换阵**：

```
theta=0,   phi=0   ->  [[0, 1], [1, 0]]     ← SWAP，会把两行对调
theta=pi/2,phi=0   ->  [[-1, 0], [0, 1]]
theta=pi/2,phi=pi  ->  [[1, 0], [0, 1]]     ← 这才是单位阵
```

消元的目标是让 `(T@A)[row,col] = e^{iφ}·cosθ·x + sinθ·y` 变成 0：

| 情形 | 对照样例取值 | 实际残留 | 正确取值 | 残留 |
|---|---|---|---|---|
| `y ≈ 0`（已经是 0，应保持不动） | θ=0 | **0.728**（把 x 换到了下面） | θ=π/2, φ=π | 4.5e-17 |
| `x ≈ 0`（要把 y 消掉） | θ=π/2 | **0.728**（y 原封不动） | θ=0 | 0 |

两个分支恰好互换了。取 `θ→π/2` 与 `θ→0` 正好是通用公式 `tanθ = -e^{iφ}x/y`
在 `y→0` 和 `x→0` 时的极限，所以**根本不需要特判**——直接用 `arctan2` 就天然覆盖：

```python
phi   = np.angle(y) - np.angle(x) - np.pi
theta = np.arctan2(np.abs(x), np.abs(y))     # y=0 -> pi/2, x=0 -> 0
```

**影响面**：任何有结构性零元素的矩阵。危险在于它**不抛异常、不报警告**，
安静地返回一个错得离谱的结果：

| 用例 | 对照样例误差 | 本实现误差 |
|---|---|---|
| `identity(4)` | 6.7e-01 | 6.2e-17 |
| `permutation(4)` | 1.7e+00 | 1.7e-16 |
| `diagonal(4)` | 1.9e+00 | 1.1e-16 |
| `block-diag(4)` | **1.4e+01** | 2.6e-15 |
| `rank-deficient` | 1.7e+00 | 5.0e-15 |
| `all-ones(4)` | 2.0e-01 | 3.1e-16 |

用随机稠密矩阵测永远碰不到这条路径（`|x|` 或 `|y|` 恰好小于 1e-15 的概率为零），
所以「10⁻¹⁶ 机器精度」的验证结论是成立的但覆盖不足。而剪枝后的神经网络权重、
one-hot 嵌入层、注意力掩码这些恰恰全是结构化稀疏矩阵。

### B2. 阈值是绝对值而非相对值

`np.abs(y) < 1e-15` 对整体尺度很小的矩阵（比如权重都在 1e-8 量级）会把正常元素
误判成零。改用 `arctan2` 后这个问题一并消失，因为不再需要阈值。

## 二、物理建模上可以更真实的地方

### P1. 奇异值可能 > 1，但 VOA 只能衰减不能放大

对照样例直接 `E = E * self.S_target`。示例矩阵里 `σ = [1.673, 1.292, 0.693, 0.056]`,
第一个就大于 1 —— 无源光衰减器做不到。真实芯片的做法是整体归一化到 ≤1，
增益放到电域（TIA 跨阻或后级数字增益）补回来：

```python
self.gain   = S[0]
self.S_phys = S / self.gain      # 全部落进 [0, 1]
```

这不只是洁癖：归一化系数直接决定了动态范围预算，σ_min/σ_max = 0.033
意味着最弱那个通道要比最强的暗 30 倍，探测端的信噪比就是从这里被吃掉的。

### P2. `return E.real` —— 光电二极管测不到实部

光电二极管测的是 `|E|²`，符号信息在平方里就没了。要拿到带符号的实部必须用
**相干/零差探测**（引一路本振光来做相位参考）。对照样例直接 `.real` 在数学上没问题，
但没有任何注释说明这背后需要一整套本振光路，初学者容易以为「测一下光强就行」。

补充一点实测：在 0.03 rad 噪声下虚部只占总能量的 0.0%，所以这**不是**数值精度问题，
纯粹是物理读出方式的说明缺失。本实现提供了 `read_coherent()` 和 `read_intensity()`
两个方法，把这个区别摆到明面上。

### P3. 没有插入损耗模型 —— 而这正是 Reck 网格的重要问题

Reck 三角网格的器件分布是**不均匀**的。示例的 4×4 双网格里，四个空间模式
参与的 MZI 数是 `[2, 6, 10, 6]`。这能直观提示损耗敏感性，但不能直接解释成四条
端到端光路：光会在 MZI 中分束并迁移到其他模式。

本实现把统一的 `mzi_loss_db` 加进了每台 MZI，并在 `report()` 里打印
`mode_mzi_count()` 与串联损耗上界估计。它们是拓扑代理量，不是光路追踪结果。

### P4. 固定偏置和动态抖动不能混在一个 `noise_std` 里

对照样例每次调用 `forward_optical_simulation` 都重新采样一次噪声，无法区分：

- 可通过控制曲线表征的固定相移偏置；
- 运行时变化、不能靠一张静态查找表消除的相位扰动；
- 会限制可达分光比、不能简化成相移偏置的分束器制造误差。

当前实现保留旧参数名 `fab_*`，但其准确含义已收窄为**固定加性相移控制偏置**；
`drift_*` 是每个输入样本独立的 i.i.d. 相位抖动，用于敏感度分析。它不声称模拟
真实热漂移的慢时间相关、空间相关或串扰。batch 中每一列现在会独立采样，不再
整批共享一份所谓“逐样本”噪声。

### P5. 噪声只加在 θ/φ 上

`diag_phases`（输出相位屏）和 `Σ`（衰减器）也都是物理器件。当前实现让相位屏
共享 `fab_phi` / `drift_phi` 语义，VOA 使用构造时采样一次的固定 `voa_rel_err`。
`detector_snr_db` 只表示平方检波或相干检波**之后**的等效相对 AWGN；它没有冒充
散粒噪声、TIA、本振或带宽模型。

### P6. 「3% 热噪声」这个说法混淆了单位

`noise_std=0.03` 是**弧度的绝对值**（约 1.7°），不是 3% 的相对误差。相移器的
典型指标一般写成 rad 或 π 的分数，本实现在 `NoiseModel` 的 docstring 里明确标注了 `rad, 1-sigma`。

### P7. docstring 写的是 "Reck/Clements"，实现的是 Reck

两者不是一回事：

| | Reck（三角） | Clements（矩形） |
|---|---|---|
| MZI 数 | N(N-1)/2 | N(N-1)/2（相同） |
| 网格深度 | 2N-3 | **N** |
| 光学深度与损耗容忍度 | 深度较大、损耗敏感 | 深度较低、通常更稳健 |

MZI 数量一样，但 Clements 的光学深度更低，并且通常对均匀损耗更稳健。
**本实现没有实现 Clements**（它的右乘消元与相位对易需要独立验证），只在
`report()` 中给出理论深度对比。Clements 也不会消除器件离散性、耦合误差或控制误差。

## 三、工程问题

| # | 问题 | 说明 | 本实现 |
|---|---|---|---|
| E1 | 只支持方阵 | `self.N = M.shape[0]`，非方阵会静默出错 | 零填充到 `max(n_out, n_in)`，多余端口暗置 |
| E2 | 不支持批量 | 一次只能算一个向量 | `x` 可为 `(n_in,)` 或 `(n_in, B)`，实测批量比循环快 **338×** |
| E3 | 用全局 `np.random` | 不可复现，且污染调用方的随机流 | 独立 `np.random.default_rng(seed)` |
| E4 | 每个 MZI 构造 N×N 全矩阵再相乘 | 编译 O(N⁵)、前向 O(N³) | 就地两行更新，降到 O(N³)/O(N²) |
| E5 | `phi` 不做 mod 2π | 会报出 `-360°` 这种无意义的值 | 折回 `(-π, π]`，也符合相移器的物理周期性 |
| E6 | 没有回环自检 | 无法确认编译结果是否忠实 | `unitary_error()` 由相移角重建 U 并比对 |
| E7 | 无输入校验 | 传错维度时报错信息很难懂 | 显式检查 + 明确报错 |

### E4 实测加速（`python benchmarks/bench_decomposition.py`）

| N | 编译（参考） | 编译（本实现） | 加速 | 单次前向（参考） | 单次前向（本实现） | 加速 |
|---|---|---|---|---|---|---|
| 8 | 1.9 ms | 3.1 ms | 0.6× | 1.08 ms | 0.96 ms | 1.1× |
| 32 | 68.5 ms | 42.2 ms | 1.6× | 38.2 ms | 35.0 ms | 1.1× |
| 64 | 1157 ms | 358 ms | 3.2× | 650 ms | 114 ms | 5.7× |
| 128 | 17509 ms | 1536 ms | **11.4×** | 3828 ms | 422 ms | **9.1×** |

小 N 时本实现反而略慢（Python 层调用开销盖过了矩阵运算的节省），N≥64 后
渐进复杂度的优势才显现出来。

**还能再快**：目前前向仍是 Python 里逐台 MZI 循环，N=128 时要跑 16256 次。
同一列（layer）内的 MZI 作用在互不相交的波导上、天然可并行，把每列向量化成
一次 numpy 操作能再快一个量级。这是下一步的优化点，本次没做。

## 四、值得肯定的地方

- 消元公式 `tanθ = -e^{iφ}x/y` 的推导是对的，`phi = -angle(-x/y)` 让 tan 落到
  非负实轴上这一步很干净
- 正向传播用 `reversed(mzi_list)` + `T.conj().T`，与 `T_k…T_1 U = D` 的分解方向
  严格对应，这里很容易搞反；对照样例在这一点上也是正确的
- 把 SVD / 编译 / 传播三层拆开，结构清晰，加物理模型时不用动核心算法

## 六、扩展验证：把固定偏置与动态抖动分开

`calibrate()` 验证的是一个有意收窄的问题：已知的加性相移控制偏置能否被其负值
抵消；每样本独立抖动能否被同一张静态修正表消除。实测结果（`examples/02`）：

| 简化模型构成 | 未校准 | 校准后 |
|---|---:|---:|
| 只有静态相移控制偏置 (fab 0.02 rad) | 4.2 bit | **48.0 bit** |
| 只有独立动态相位抖动 (drift 0.02 rad) | 3.9 bit | 3.9 bit |
| 两者都有 (fab 0.02 + drift 0.005) | 4.2 bit | 5.9 bit |

48 bit 是模型内精确相消的数值结果，不是现实芯片校准能力。真实分束器误差可能
限制 MZI 的可达范围，真实热漂移也通常具有时间和空间相关性；两者均未由这张表验证。

`calibrate()` 只补偿网格与输出相位屏的加性相移偏置，不补偿分束器误差、VOA
设定误差或插损。`examples/03` 的 B 段只是统一器件插损下的系统敏感度演示。

## 七、当前模型边界

当前版本已修正 batch 共享动态抖动、探测噪声加在复光场上、输出相位屏始终理想、
错误输入形状被 `reshape` 静默接受、示例导入旧安装包，以及把空间模式计数误称为
实际光路等问题。执行随机方阵、非方阵、复输入和 batch 性质测试后：

- 理想探测前光场满足 `E = (M @ x) / gain`；
- 相干读出满足 `Re(M @ x)`，直接读出满足 `|M @ x|²`；
- batch 每列动态抖动独立，同一随机种子仍可复现；
- 错误形状、非有限数、复权重矩阵、非酉分解输入和无效噪声参数均显式拒绝。

项目仍是线性光学**电路级敏感度模型**，不是电磁场、器件工艺或完整光电系统模拟器。
它没有足够信息预测激光功率、DAC/ADC、TIA、系统能耗/延迟、真实 ENOB 或商用芯片性能。
